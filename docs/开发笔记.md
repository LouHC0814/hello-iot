# 第一版开发笔记：先走通数据流程

## 这次做了什么

原来的仓库只有计划。这一版先把「得到读数 → 保存记录 → 画图 → 生成统计」做成可以运行的程序，后续再换成真实传感器。

所有读数都标注为 `simulated`。代码中的正弦趋势和随机噪声只是演示模型，不能拿来代表真实天气、传感器误差或设备性能。

## 顺着这条链读代码

1. `Reading`：一个采样点，包括时间、温度、湿度、数据来源。
2. `simulate()`：每次产生一个采样点；固定随机种子便于复现实验。
3. `collect()`：边接收边写入 CSV，每条写完立即刷新文件缓冲。
4. `summarize()`：根据实际保存的记录计算统计，并判断有没有采满。
5. `main()`：处理参数、选择一次生成或窗口回放、保存曲线和摘要。

`simulate()` 使用 `yield`：可以把它理解成「每叫一次，就交出下一条读数」。以后读串口时也可以采用这种形式，因此保存数据的部分不必全部重写。

CSV 是持久记录，绘图窗口只是观察方式。提前关窗口或者按 Ctrl+C，程序会保留已经采到的部分，并把摘要里的 `complete` 设为 `false`（如果未采满）。不要把「运行没有报错」等同于「采集了全部数据」。

这里的逐条刷新是刷新 Python 文件缓冲；它不保证突然断电时磁盘上的最后一条记录一定完整。

## 时间为什么要带时区

例如 `2026-10-13T09:00:00+08:00` 表示北京时间上午九点。CSV 保留时区，曲线横轴也按对应时区显示。没有显式时区的 `--start` 按北京时间处理。

`--interval` 决定记录里的时间差，`--refresh` 决定窗口播放速度。为了短时间看到一小时的变化，两者可以不同。

## 本机环境注意事项

- 使用 Python 解释器绝对路径，避免调到另一套没有依赖的环境。
- 沙箱里的 `LOCALAPPDATA` 可能被重定向；启动脚本从用户配置文件目录定位常见的 Python 3.13 安装路径，也支持手动指定解释器。
- PowerShell 中用 `& $demoPython` 调用解释器；路径放进双引号或变量，用户名含撇号也能正常处理。
- matplotlib 缓存写入项目的 `.runtime`。启动脚本也会把 IPython / Jupyter 的配置目录设置到该目录下，为后面的实验做准备。
- CSV 使用 UTF-8 BOM，方便 Excel 识别编码。PowerShell 启动脚本也使用 UTF-8 BOM，以兼容 Windows PowerShell 5.1 的中文解析。
- 有中文字体时绘制中文标签；找不到中文字体时使用英文图表标签，避免缺字。命令行提示和文档仍为中文。

## 这版检查覆盖什么

- 固定种子是否可复现，增加样本数是否保留原来的前缀。
- 时间间隔、来源标记和模拟值范围。
- 非法参数是否被拒绝，包括非有限数和时间溢出。
- CSV 与采集列表是否一致。
- 关闭窗口、Ctrl+C 是否保留已采集记录。
- 均值、最小值、最大值与单样本统计。
- 命令行时间解析。

此外，需要实际运行绘图命令，确认 PNG、CSV 和 JSON 都生成。GitHub Actions 在 Linux 上检查默认模式；桌面窗口回放需要另外在本机图形环境验证。

## 之后接入硬件时

先确定 ESP32 发来的数据格式，例如一行包含温度、湿度；再处理缺行、乱码、非法数值与断线。真实数据源必须使用不同的 `source` 标记，不能继续把实测数据记成 `simulated`。

MQTT 和网页放在串口采集稳定之后添加，每一步都保留能复现问题的数据和运行说明。
